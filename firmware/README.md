# Прошивки Vestang

## Куда что класть

- `original/` — сырые дампы **как есть**, ничего не переименовывать «на глаз»
  и не редактировать. Это референс, с которым сверяется всё остальное.
- `extracted/` — результат распаковки (binwalk, unsquashfs, отдельные секции).
  В git не попадает (см. `.gitignore`), всегда воспроизводится из `original/`.

## Правила именования файлов в `original/`

```
<устройство>_<версия-или-дата>_<как-снято>.bin
```

Примеры:

```
vestang_v1.2.3_ota.bin        # скачано с сервера обновлений / из приложения
vestang_unknown_spiflash.bin  # вычитано программатором с чипа
vestang_2026-09-14_uart.bin   # слито через загрузчик по UART
```

Если версия неизвестна — `unknown`, потом переименуем, когда найдём строку версии.

## Что записать по каждому дампу

Для каждой прошивки заводим `notes/<имя-файла>.md` и фиксируем:

- откуда взялась (URL, программатор + модель чипа, UART/JTAG, разбор устройства);
- размер, sha256;
- если снималось с железа — сколько раз читали и совпали ли дампы побитно
  (один прочитанный дамп ничего не гарантирует: плохой контакт = битые байты).

## Первый проход по новому дампу

```sh
sha256sum firmware/original/<file>
file firmware/original/<file>
binwalk -E firmware/original/<file>          # энтропия: где сжатое/шифрованное
binwalk firmware/original/<file>             # сигнатуры
strings -n 8 firmware/original/<file> | less # версии, урлы, имена функций
```

Распаковка — только в `extracted/`:

```sh
binwalk -e -C firmware/extracted firmware/original/<file>
```

Если энтропия ровно ~1.0 по всему файлу — прошивка сжата или зашифрована целиком,
сигнатур не будет; тогда идём от заголовка/загрузчика.
