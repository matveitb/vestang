# Карта флеша M74.9 и калибровок

Адреса — смещения в образе (флеш `0x08000000` + смещение). Цифры для
I862BB04; у BB03 и BB02 разметка та же, сдвинуты отдельные адреса внутри
областей.

## Что лежит в 0x1000..0x100000

| Область | Что |
|---|---|
| `0x00000..0x00FFF` | во всех 27 дампах `FF`: загрузчик сюда не попадает и не пишется |
| `0x01000..0x013FF` | таблица векторов, 256 штук; SP = `0x20020000`, Reset = `0x08080001` |
| `0x01400..~0x41000` | код, сегмент 1 |
| `0x416D0..0x43E98` | таблица калибровок: u32 число (2545) + указатели на дескрипторы |
| `0x44D58..0x50300` | дескрипторы калибровок (оси, кривые, карты, значения) |
| `0x50330` | заголовок `PHDR`: `15.01.2015`, `15.11.2023` |
| `0x51548..0x54E60` | имена модулей: `SOFTTIMER`, `KNOCK_DRIVER`, `IMMO`, `ISO14229EOL`, `ECUID`, `COMR`, `UART`, `GPIO`, `IGNCTRL`, `MEMMAN`, `EMEEP`, `IC_ETC`, `IC_EMS`, `ISO15765_2`, `FLASH`, `SPISCH` |
| `0x52A64` | таблица CRC-32 (см. `checksum.md`) |
| `0x53DBC` | константы `expand 32-byte k` / `expand 16-byte k` (ChaCha/Salsa) |
| `0x54F00..0x5FFFF` | пусто |
| `0x60000..0x77000` | **калибровки** |
| `0x624B0` | `I862BB04`, `I862BB04_w2346b4` |
| `0x690F8` | `Vesta_21129`, `M74.9` |
| `0x63BD0..0x63C23` | блок круиза (`cruise.md`) |
| `0x77000..0x7FFF7` | пусто |
| `0x7FFF8` / `0x7FFFC` | компенсатор / КС калибровок |
| `0x80000..0xB9F00` | код, сегмент 2: Reset (`0x80000`), прикладная логика, модуль круиза `0x82E80..0x9A530`, обработчики прерываний `0xB6xxx` |
| `0xB9F00..0xFFFF7` | пусто |
| `0xFFFF8` / `0xFFFFC` | компенсатор / КС кода |

Запись `0x1000..0x100000` целиком накрывает и код, и калибровки, и обе КС.
Круиз попадает туда полностью: флаги в калибровках, код в сегменте 2.

## Что меняют файлы тюнеров относительно стока

| Файлы | Калибровки | Вне калибровок |
|---|---|---|
| `S_CVN… 2023`, `GBO-4 2023`, `startpower 2024 I865BB02` | 2.3–3 тыс. байт | ничего |
| `+tun`, `+tun KK` | 4–7 тыс. байт | 1 байт кода + КС кода |
| `MR2(v2)…` (двухрежимные) | ~2.4 тыс. байт | ~170 тыс. байт кода |
| `…2024__I862BB04_CCon…` | ~7.8 тыс. байт | ~340 тыс. байт: это целиком I865BB02 под строками версии I862BB04, КС подогнаны под заводские BB04 (`cruise.md`) |

Байт кода у `+tun`: BB04 `0xB4032`, BB03 `0xB3C02` — в ветке `switch`
`movs r7, #3` заменён на `movs r7, #0`. Что это за состояние, не разобрано.

## Калибровки: таблица дескрипторов

Формат снят с геттеров `0x48DC..0x4A8C` и описан в `tools/calmap.py`.
Кратко: байт `+0` — тип элемента (`u8 s8 u16 s16 u32 s32`), байт `+1` — вид
(значение / кривая / карта), u16 `+2` — класс хранения.

BB04, 2545 объектов:

| вид | сколько |
|---|---|
| значения | 909 |
| массивы | 391 |
| кривые | 355 |
| карты | 298 |
| оси | 259 |
| RAM-величины с пределами в калибровках | 284 |
| RAM-массивы | 14 |
| не опознано (списки индексов в хвосте таблицы) | 35 |

Проверки:

- у всех 653 кривых и карт число точек совпадает с осями;
- описанные объекты не перекрываются;
- покрыто 97.8% непустых байт калибровок (88 210 из 90 166) на всех трёх
  софтах. Непокрытое — 69 мелких участков, крупнейший 351 байт
  (`0x62FAC..0x6310B`).

Индексы объектов совпадают между софтами не всегда: круиз и ограничитель —
`#574` и `#590` везде, а признак поддержки — `#973` в BB04/BB02 и `#979`
в BB03.

Имён и физических единиц в прошивке нет — это даёт только A2L. Входы осей
видны как адреса RAM, по ним карты группируются по общей величине.

```sh
python3 tools/calmap.py list  файл.bin            # все калибровки
python3 tools/calmap.py show  файл.bin 587        # значения с осями
python3 tools/calmap.py diff  сток.bin тюнинг.bin # что поменял тюнер
python3 tools/calmap.py cover файл.bin            # покрытие
```

`diff` на парах тюнера `+tun` против `+tun KK` выдаёт ровно объекты круиза
(`#574`, `#590`, у BB04 ещё `#973`) и КС `0x7FFFC` — тот же результат, что
в `cruise.md`, но уже без поиска руками.

## Конфигурация CAN

Непокрытый картой участок `0x62FAC..0x632DC` — таблицы CAN, их передаёт
драйверу `0x94EB6 → 0xAB468`. Приём: 39 сообщений (таблица `0x63048`).
Передача: 21 сообщение — ID u32 `0x631D4`, длины `0x63228`, номера
объектов `0x63258`, периоды в мс `0x63284`, смещения `0x632B0`.
Буферы передачи в RAM: `0x200056B8 + 8 × номер`.
