# Круиз-контроль: как задаётся на разных софтах

## Ответ

Круиз задаётся **двумя байтами калибровки** плюс заводским признаком
поддержки в софте. Блок лежит в регионе калибровок:

| Софт | признак поддержки | круиз-контроль | ограничитель скорости |
|---|---|---|---|
| I862BB03 | `0x63BD8` = `0001` | `0x63BEA` | `0x63BEB` |
| I862BB04 | `0x63BE8` = `0000` | `0x63BFA` | `0x63BFB` |
| I865BB02 | `0x63BE8` = `0001` | `0x63BFA` | `0x63BFB` |

`0` = выключено, `1` = включено. У BB03 весь блок сдвинут на `-0x10`.

Заводское состояние:

| Софт | поддержка | круиз | вывод |
|---|---|---|---|
| I862BB03 | есть | **выкл** | включается калибровкой |
| I862BB04 | **НЕТ** | выкл | калибровкой не включается |
| I865BB02 | есть | **вкл** | работает из коробки |

## Как это доказано

На I862BB03 у стока и у всех трёх сборок `+CC` **код побайтно идентичен** —
различия только в калибровках. Фильтр «сток отличается, все три `+CC`
согласованы между собой» по 780 записям таблицы калибровок оставляет
ровно два байта:

```
#212  0x63BEA   сток 00 -> +CC 01
#213  0x63BEB   сток 00 -> +CC 01
```

Это уже не корреляция «заодно с софтом»: тюнер меняет эти байты
независимо от кода. По всем 19 образам совпадение стопроцентное —
`1` ровно там, где круиз заявлен, `0` где нет.

Соседи по блоку одинаковы во всех софтах, что и позволяет опознать блок
без A2L:

```
#n-5 = 03FF        #n-4 = поддержка   #n-3 = 00000046
#n-2 = 40          #n-1 = 03          #n = круиз   #n+1 = ограничитель
```

## Почему на I862BB04 тюнер не ставит флаг

У BB04 признак поддержки = `0000`, в отличие от BB03 и BB02. Вместо
активации флага тюнер подменяет **весь код** на I865BB02:

- область кода файла `..._I862BB04_CCon_E2.bin` побайтно идентична
  `I865BB02` — 0 отличий;
- отличий от сборки BB02 всего 50 байт: идентификаторы и КС;
- обе КС подогнаны компенсаторами под заводские значения **BB04**
  (`0A6E4403` / `937D8A1D`).

Блок отвечает диагностике как I862BB04, а исполняет код I865BB02. Это и
есть «не досконально выявленные проблемы, в том числе и по активации
круиза» из `ИнфоЗамены.txt`.

Практическое следствие: такая прошивка наследует требования BB02 —
перепиновка разъёма **F2 → A2** (TSB1) и потеря данных регистратора.

**Не проверено:** заработает ли круиз на BB04, если выставить признак
поддержки в `0001` вместе с флагами. Тюнер этого не делает. Статически
подтвердить нельзя — нужна проверка на машине.

## Инструмент

```sh
python3 tools/ccflag.py show firmware/original/*.bin   # состояние
python3 tools/ccflag.py on  вход.bin выход.bin         # включить
python3 tools/ccflag.py off вход.bin выход.bin         # выключить
```

Правка сохраняет **заводскую** КС компенсатором на `0x7FFF8` — так же, как
делает тюнер. Включение круиза на стоке BB03 меняет ровно 6 байт:
два флага и компенсатор. Round-trip on→off возвращает исходный файл
байт в байт.

## Идентификаторы (для перештамповки)

| Смещение | Что |
|---|---|
| `0x624B0` | основной ID |
| `0x624C0` | ID сборки (`I865BB02_w2345b3`) |
| `0x624D4` | дубль ID |
| `0x624E4` | дата (`20231115`) |
| `0x69030` | номер по каталогу (`8450044227`) |
| `0x690B8` | дата + экокласс (`15112023EURO-5+`) |
| `0x76E8B` | дубль ID |

## Таблица калибровок (замена A2L)

`tools/caltable.py` разбирает дескрипторы: `указатель(4) | тип(2) |
флаги(2) | количество(4)`.

| Софт | Записей | Таблица | Калибровки |
|---|---|---|---|
| I862BB03 | 780 | `0x493E8..0x50EA8` | `0x619A4..0x76B95` |
| I862BB04 | 802 | `0x49804..0x514FC` | `0x619A8..0x76EE1` |
| I865BB02 | 802 | `0x49694..0x51378` | `0x619A8..0x76F09` |

## Истинный код против заявленного ID

Отпечаток кода (CRC над `0x1000..0x5FFFF` + `0x80000..0xFFFF8`, то есть
**без** компенсатора) показывает, что реально исполняется:

- на коде I862BB03 — 4 файла, на I862BB04 — 4, на I865BB02 — **7**
  (включая все три `CCon`, заявленные как BB04);
- четыре MR2 (двухрежимные ГБО) несут собственный, пропатченный код —
  их калибровки при этом совпадают с обычными сборками, то есть
  MR2 = базовый файл + патч кода.
