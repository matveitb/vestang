# Круиз-контроль в M74.9: как включается

## Итог

Круиз включается **только калибровками**. Код не меняется ни на байт.

| Софт | что менять | сколько байт |
|---|---|---|
| I862BB03 | `0x63BEA` = 01, `0x63BEB` = 01 | 2 |
| I862BB04 | `0x63BE9` = 01, `0x63BFA` = 01, `0x63BFB` = 01 | 3 |
| I865BB02 | уже включено с завода | — |

Плюс пересчёт КС калибровок в `0x7FFFC`.

| адрес (BB04) | адрес (BB03) | назначение |
|---|---|---|
| `0x63BE9` | `0x63BD9` | признак поддержки круиза |
| `0x63BFA` | `0x63BEA` | круиз-контроль |
| `0x63BFB` | `0x63BEB` | ограничитель скорости |

У BB03 весь блок сдвинут на `-0x10`, и признак поддержки там уже выставлен
с завода — поэтому хватает двух байт. У BB04 признак поддержки нужно
доставить самому.

## Доказательство

Пары тюнера `+tun` против `+tun KK` — одна база, один тюнинг, различие
только в круизе:

```
I862BB04_Vs008_70_E2+tun.bin -> ... KK.bin   (7 байт)
  063BE9  00   -> 01
  063BFA  0000 -> 0101
  07FFFC  КС калибровок пересчитана

I862BB03 E2+tun.bin -> ... KK.bin            (6 байт)
  063BEA  0000 -> 0101
  07FFFC  КС калибровок пересчитана
```

`tools/ccflag.py on` воспроизводит оба файла тюнера **байт в байт**.

## Опознание блока без A2L

Блок находится по соседям в таблице калибровок, без привязки к адресам:

```
#n-5 = 03FF      #n-4 = признак поддержки    #n-3 = 00000046
#n-2 = 40        #n-1 = 03                   #n = круиз   #n+1 = ограничитель
```

Остальное содержимое блока (`#204..#211`, `#214`) во всех 27 образах
побайтно идентично: `26`, `200`, `200`, `[3,255]`, `[0,0x4600,64,-64]`,
`64`, `3`, `0`. Значения `26 / 200 / 200` по порядку величины похожи на
пороги скорости, но масштаб **не подтверждён** — без A2L это догадка.

## Два стиля работы с КС

| Тюнер | Компенсатор `0x7FFF8` | КС `0x7FFFC` |
|---|---|---|
| файлы `S_CVN...` | подбирает, чтобы КС осталась **заводской** | не меняется |
| файлы `...+tun` | не трогает (`FFFFFFFF`) | **пересчитывает честно** |

`ccflag.py` по умолчанию пересчитывает честно; с ключом `--pin` сохраняет
заводскую КС компенсатором.

## Инструмент

```sh
python3 tools/ccflag.py show firmware/original/*.bin
python3 tools/ccflag.py on  вход.bin выход.bin          # честный пересчёт КС
python3 tools/ccflag.py on  вход.bin выход.bin --pin    # сохранить заводскую КС
```

## Что оказалось неверно (исправлено)

- **«На BB04 одних флагов недостаточно, нужен ещё блок `#224..#228`».**
  Неверно. Блок `#224..#228` (в BB04 пары схлопнуты в одинаковые значения)
  тюнер не трогает вообще — хватает трёх байт. Схлопнутые пары там
  относятся к чему-то другому, а не к готовности круиза.
- **«Круиз активируется конфигурированием ЭБУ через сканер».**
  Неверно, включается прошивкой. Предположение строилось на том, что блок
  не адресуется кодом напрямую, — но это говорит лишь о способе доступа.

## Где код круиза — открытый вопрос

Дифом его не найти: в парах `+tun` / `+tun KK` область кода идентична,
функция присутствует в обеих версиях и просто заперта флагами.

Статический поиск читателя флагов результата не дал. `tools/xref.py`
отслеживает базу в регистре (literal pool, `movw`/`movt`, `add`, `mov`)
и находит обращения к обычным калибровкам — например
`084B76 ldrh r3,[r3] -> кал 063C24`, — но к блоку `0x63BD0..0x63C23`
обращений нет ни в одном сегменте кода. Граница проходит ровно по блоку:
`0x63C24` читается, весь блок — нет.

Значит блок читается не адресом из кода, а обобщённым механизмом:
копией в RAM при инициализации либо доступом по индексу. Чтобы это
добить, нужен один из вариантов:

1. A2L/DAMOS — сразу дадут имена и способ доступа;
2. эмуляция старта (Unicorn) — видно, куда блок расходится по RAM;
3. трассировка от обработчика кнопок круиза по CAN вниз.
